# 기존 삼종 계산 서버의 배포 준비 소스

기존 개인용 Sites MCP 엔진의 어댑터와 Worker를 기존 앱 저장소에서 검토·재현하기 위한 소스다. 새 앱이나 새 Sites 프로젝트를 생성하지 않는다. 기존 Sites 원본 저장소의 배포 커밋은 `e8ef566f99335e5b3c04b8aa00a19e348ffb0740`이며, 현재 운영 도구는 `0.1.0`을 반환한다. 여기의 `0.2.0-candidate`는 로컬 검증 후보이며 아직 배포하지 않았다.

## 재현

Node 22, pnpm 9.15.0에서 저장소 루트의 `pnpm install --frozen-lockfile`을 먼저 실행한다. 이어 루트에서 `pnpm exec tsc -p chatgpt-plugin/tsconfig.json`으로 어댑터까지 검사한다.

이 디렉터리에서 다음 순서로 실행한다.

```sh
npm ci
npm run snapshot
npm run build
npm test
npm run validate
```

`snapshot`은 **현재 체크아웃**의 앱 계산 모듈 86개를 `engine-source/`에 복사하고 SHA-256 출처 목록을 생성한다. `build`는 해시가 바뀌면 실패한다. API 시험은 모든 복사본과 원본의 해시·바이트 일치, 인증 경계 보존, 기존 응답 필드, 시간 감사 전달, 양음력·날짜 이월·DST 및 미지원 오류를 검증한다. 시험 입력은 합성 사례다. 기존 원본 저장소 및 별도 Sites 소스의 작업 중 수정사항은 덮어쓰지 않는다.

계산 모듈의 이중 관리를 피하기 위해 생성된 스냅샷/출처 목록과 번들은 Git에 넣지 않는다. 배포할 때는 반드시 고정한 동일 PR 커밋에서 재생성한다. `.openai/hosting.json`은 기존 프로젝트의 것을 보존하며 Git과 새 생성 동작에서 제외한다. 해당 파일이 없는 로컬 검증 빌드는 배포 준비가 완료된 패키지로 취급하지 않는다.

## 계산 기준과 제한

- 사주는 경도 보정 기본 켬, 균시차 기본 끔을 유지한다. 보정량의 기존 반올림을 유지하면서 전일/익일과 연도·윤년 날짜를 함께 이월한다. 원본 양력일과 출생입력은 그대로 반환한다.
- 자미두수는 원본 시계시각·기존 중주파 규칙을 사용한다. 서양차트는 원본 현지 시계시각을 IANA 시간대/DST로 UTC 변환한다. 사주 보정시각을 두 체계에 재사용하지 않는다.
- 해외 또는 한국의 과거 표준시/DST가 UTC+9와 다른 삼종 입력은 `SAJU_ZIWEI_TIMEZONE_UNSUPPORTED`로 거부한다. 서양 단독 모듈의 DST 지원과 구분한다. 중복 시각의 fold 미지정과 존재하지 않는 시각도 명시적 오류다.
- 음력 윤달은 양력으로 변환해 입력해야 한다. 실제 일반 음력 변환은 의존성으로 시험했다.
- 만세력 1.0.8의 년·월주는 날짜 단위다. **절기 순간의 전후 정확성은 미지원**이며 경고한다. 시진 경계 ±5분은 실제 모듈로 비교한 시험 범위이며 출생시각 오차 확률이 아니다. 야자시/조자시 유파 대조도 미검증이다.
- 신강·용신은 기존 규칙 지수다. 자미두수 유파·사화·운기와 서양 천문력·Placidus 하우스의 독립 대조는 미완료이며 API 경고/설명에서 검증 완료와 분리한다. 기존 해석 문장 전반의 의미 검수는 별도 남아 있다.

## 승인 후 반영 절차

1. 기존 PR의 검증한 커밋과 원본 로컬 변경사항을 재확인한다. Vercel 앱은 이 PR 브랜치의 Preview를 검수한 뒤 별도 승인된 경우에만 main/Production에 반영한다. GitHub push는 기존 브랜치 Preview를 갱신할 수 있다.
2. Sites는 Vercel과 다른 원본 저장소·배포 대상이다. 기존 프로젝트의 `get_site`, 버전 목록과 기존 원본 저장소 HEAD를 다시 읽고 동시 변경을 보존한다. 기존 `.openai/hosting.json`, 인증, endpoint, 공개 범위를 그대로 유지한다.
3. 이 디렉터리의 어댑터/Worker 및 동일 커밋에서 재생성한 86개 스냅샷과 출처 목록을 기존 Sites 체크아웃에 반영한다. 기존 검증과 여기의 합성 API 시험을 모두 재실행한다. 원본에서 변경된 README 등은 덮어쓰지 않는다.
4. 운영 반영 승인을 받은 후에만 기존 Sites 소스의 scoped credential과 공식 source helper를 사용해 정확한 소스를 커밋·전송·패키징하고, **같은 소유자 전용 프로젝트**의 저장 버전을 배포한다. 모든 Sites URL 배포는 운영 배포다. 새 프로젝트·DB·권한·주소·비용 자원을 만들지 않는다.
5. 실제 연결 도구의 상태에서 후보 버전, 계산 응답의 engineVersion/timeAudit 및 세 체계별 시간 기준, 합성 경계 입력, 기존 응답 필드 보존을 재확인해야 운영 반영 완료다. 플러그인 스킬 1.1.0과 서버 버전은 별개다.

## 롤백과 현재 장애

- Vercel: 기존 Production을 유지하고 새 Preview 실패 시 승격하지 않는다. 승인 후 반영한 변경을 되돌릴 경우 기존 정상 커밋/배포로 롤백한다.
- Sites: 변경 전 저장 버전 1과 소스 커밋을 유지한다. 승인된 롤백이 필요하면 기존 버전 목록의 해당 버전을 같은 프로젝트에 공식 배포하고 상태 및 실제 도구를 재조회한다. 버전 ID·배포 ID는 기존 비공개 프로젝트에서 조회하며 공개 문서에 계정 식별정보/비밀값을 기록하지 않는다.
- Vercel 상세 배포 조회는 대상 팀 범위의 403으로 차단됐다. 다른 계정으로 우회하지 않았다. GitHub의 해당 커밋 Vercel success 상태와 로컬 전체 빌드는 확인했지만, 원격 빌드 로그·브라우저 Preview는 미검증이다.
- Sites의 현재 소유자 권한, 저장 버전 1 및 실제 연결은 읽기 전용 확인했다. 원본 소스는 로컬에 있고 HEAD가 저장 버전과 일치한다. 새 원격 쓰기 credential 발급·소스 push·운영 재배포는 이번 범위에서 실행하지 않았다. 운영 승인이 남아 있으며 원격 쓰기/배포 성공을 주장하지 않는다.
